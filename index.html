Reading the paper论文解读

Imagine running a supermarket and deciding each day how many cartons of milk to order. Order too few and you lose sales; order too many and the leftovers expire. Now add one twist: when brand B is out of stock, some customers switch to brand A. How much A you should order then depends on how much B you have left.

假设你经营一家超市，每天决定订多少盒牛奶。订少了缺货、丢销售；订多了卖不完会过期。再加一个条件：顾客想买 B，B 缺货时有人愿意改买 A。于是 A 订多少，也取决于 B 还剩多少。

The authors ask whether a GPU can compute the optimal ordering policy faster when both remaining shelf life and substitution are modelled. "Optimal" means maximising long-run average daily profit, within the model and its order cap.

作者的问题是：同时考虑剩余保质期和替代需求时，能否用 GPU 更快地算出最优订货策略。这里“最优”指在模型和订货上限内，最大化长期平均每日利润。

Stock has an age, not just a total库存要记录“年龄”，不只是总量

Inventory is a vector I = (I1, …, IM), where Ir counts items with r days of shelf life left. (3,2,1) and (0,0,6) both hold 6 items, but the first has 3 that expire tonight. Timing matters too: an order placed today arrives tomorrow morning, so it cannot serve today's customers.

库存写成向量 I = (I1, …, IM)，Ir 是剩余 r 天保质期的件数。(3,2,1) 和 (0,0,6) 总量都是 6，但前者有 3 件今晚就会报废。还要记住时间点：今天下单，明天早上到货，今天的订单不能卖给今天的顾客。

State transition F(q, I, d): watch one day unfold状态转移 F(q, I, d)：动手看一天发生了什么

FIFO: customers take the oldest item first. Change demand and order size to see what is sold, spoiled, aged and delivered.FIFO：顾客先拿最老的。调需求和订货量，观察卖出、过期、变老、到货。
Sold today今天卖出Expires tonight今晚过期Carried over (one day older)留到明天（变老一天）Arrives tomorrow morning明早到货

Intuition直觉

"Markov" means today's age profile is enough to describe tomorrow; no history is needed. The authors' job is to precompute that "state → order" lookup table.

“马尔可夫”指知道今天的库存年龄分布，就足以描述明天的变化，不必回看历史。作者要做的事，就是提前把那张“状态 → 订货量”的查询表算出来。

What value iteration computes价值迭代在算什么

Today's profit alone is not enough: ordering less saves cost today but may cause a stock-out tomorrow. Each candidate order is scored as today's reward plus the long-run value of the stock it leads to.

只看当天利润不够：今天少订省了成本，明天可能缺货。每个候选订货量都要比较“今天的收益 + 它导致的明天库存的长期价值”。

Formula (average-reward Bellman equation, written with max for profit maximisation)公式（平均收益 Bellman 方程，按利润最大化修正为 max）
π + V(I) = s·E[min(d, Y)] + maxq{ −cq + E[V(F(q, I, d))] }

Y = Σr Ir is total stock. V(I) is a relative value (unchanged by adding a constant); π is the unique optimal long-run average daily profit.

Y = Σr Ir 是总库存。V(I) 是相对价值（加任意常数不变），π 是唯一的最优长期平均日利润。

  1. InitialiseGive every state a starting value (the paper uses expected sales Esalej).
  2. Freeze the old tableCopy V into W. Every state in a sweep reads only W, so states are independent — this is what makes the sweep parallel.
  3. Expectation per state and actionFor each order quantity, weight W(next state) by the demand probabilities.
  4. Take the bestKeep the highest-scoring order and update Vj.
  5. Check the spanStop when span(V − W) = max(Vj − Wj) − min(Vj − Wj) < 10⁻⁴; the bounds of V − W then bracket π.
  1. 初始化给每个状态一个初值（论文用期望销售 Esalej）。
  2. 冻结旧表把 V 复制成 W。同一轮所有状态都只读 W，彼此独立——这正是可以并行的原因。
  3. 逐状态、逐动作求期望对每个订货量，按需求概率加权 W(下一状态)。
  4. 取最优选得分最高的订货量，更新 Vj。
  5. 检查 spanspan(V − W) = max(Vj − Wj) − min(Vj − Wj) < 10⁻⁴ 时停止，此时 V − W 的上下界夹住 π。

Why two products blow up the computation两个商品为什么让计算量暴涨

One product has N = (Q̄+1)M states; two products have (Q̄a+1)M(Q̄b+1)M. Each state must also try (Q̄a+1)(Q̄b+1) order pairs and every demand/substitution event, times the number of sweeps.

单商品状态数 N = (Q̄+1)M；两商品是 (Q̄a+1)M(Q̄b+1)M。每个状态还要遍历 (Q̄a+1)(Q̄b+1) 种订货组合、所有需求/替代事件，再乘以迭代轮数。

How substitution is modelled替代需求怎么建模

Substitution runs one way: when B is short, each customer who missed B independently switches to A with probability γ. The number switching is u ~ Binomial(x, γ), where x is B's shortfall. A must serve its own demand plus this extra demand, so the two orders have to be decided jointly.

方向是单向的：B 缺货时，每位没买到 B 的顾客独立地以概率 γ 改买 A。转来的人数 u ~ Binomial(x, γ)，x 是 B 的缺口。A 要同时满足自己的需求和这部分替代需求，所以两个订货量必须联合决定。

Exactly what CUDA acceleratesCUDA 加速的到底是哪一段

In the sequential code, the nested substitution loops (Algorithm 3, lines 14–19) take over 95% of the runtime. Only that part moves to the GPU. For one fixed state j, each block handles one order pair, each thread in the block computes one demand event's contribution P(event)·W(next state), and thread 0 sums them in shared memory.

顺序程序里，处理替代需求的嵌套循环（Algorithm 3 第 14–19 行）占 95% 以上时间。作者只把这一段搬到 GPU：对一个固定状态 j，每个 block 算一个订货组合，block 内每个 thread 算一个需求事件的贡献 P(事件)·W(下一状态)，最后由 0 号线程在 shared memory 里求和。

Thread mapping (one fixed state j)线程映射（固定一个状态 j）

The outer loop over states still runs on the CPU. Each state costs one kernel launch and one device→host copy, which is why communication takes 16–24% of the paper's GPU runtime.

外层的状态循环仍在 CPU 上逐个进行；每个状态都要一次 kernel 调用和一次 device→host 拷贝，这正是论文中通信占 16–24% 的来源。

Remember these four points记住这四句

① The state must record remaining shelf life, not just the total. ② Ordering trades today's cost against future stock value, hence MDP + value iteration. ③ Substitution couples the two products' decisions, so states and work grow fast. ④ The costliest expectation is moved to the GPU: up to about 11.7× overall, about 19.6× for the substitution part alone.

① 状态要记录剩余保质期，不能只记总量。② 订货要权衡当天成本与未来库存价值，所以用 MDP + 价值迭代。③ 替代让两个商品的决策耦合，状态与计算量迅速增长。④ 作者把最耗时的期望计算交给 GPU，整体最高约 11.7×，替代部分本身约 19.6×。

Quiz: stock (3,2,1), demand 2, order 5. Why is tomorrow (2,1,5) and not (3,2,5)?小测：库存 (3,2,1)，需求 2，订货 5，明天为什么是 (2,1,5) 而不是 (3,2,5)？
Sell: 2 of the 3 oldest items are sold. Spoil: the remaining 1 expires tonight. Age: the 2 items with 2 days left now have 1; the 1 item with 3 days left now has 2. Deliver: 5 new items arrive as the freshest layer. Hence (2,1,5). (3,2,5) ignores both sales and ageing.
卖出：最老的 3 件里卖掉 2 件。过期：剩下的 1 件今晚过期。变老：剩 2 天的 2 件变成剩 1 天，剩 3 天的 1 件变成剩 2 天。到货：明早 5 件作为最新鲜的一层。所以是 (2,1,5)。(3,2,5) 忽略了销售和变老。
Quiz: why can all states in one sweep run in parallel?小测：为什么同一轮迭代里所有状态可以并行？
Each new value reads only the frozen W from the previous sweep, never a V computed in the same sweep. There is no read-after-write dependency between states.
每个状态的新值只读取上一轮冻结的 W，不读同轮刚算出的 V。状态之间没有写后读依赖。

How the reproduction was done复现过程

The original source code is unavailable, so this is an independent implementation rather than a transcription. NumPy is the CPU reference and CuPy evaluates the same batched Bellman update on an NVIDIA GPU. Both backends share state enumeration, transition events, immediate rewards, stopping rule and numerical precision, so their results can be compared digit by digit.

原始源码不可得，所以这是一次独立实现，而不是逐行转写。NumPy 作为 CPU 参考，CuPy 在 NVIDIA GPU 上执行同一个批量 Bellman 更新。两个后端共享状态枚举、转移事件、即时收益、停止规则和数值精度，因此结果可以逐位比较。

Order of events within a day (as adopted)一天内的事件顺序（复现采用的约定）

  1. ObserveIn the morning, see both products' stock by age.
  2. OrderChoose (qa, qb) at cost caqa + cbqb.
  3. DemandIndependent Poisson demand for A and B, served FIFO from existing stock.
  4. SubstituteEach unmet B customer switches to A with probability γ; A's own demand and the accepted substitution demand are served together from A.
  5. Age and spoilUnsold items with 1 day left are discarded; the rest age by one day.
  6. DeliverToday's order becomes the freshest layer of the next state.
  1. 观察早上看到两个商品各年龄层的库存。
  2. 下单选择 (qa, qb)，成本 caqa + cbqb。
  3. 需求发生A、B 各自 Poisson 需求，按 FIFO 从现有库存出售。
  4. 替代B 未满足的每位顾客以概率 γ 转向 A；A 的原始需求与替代需求一起由 A 库存满足。
  5. 老化与过期剩 1 天的未售商品报废，其余年龄减一。
  6. 到货今天的订单成为下一状态中最新鲜的一层。
Intuition直觉

The paper does not spell this order out. Whether orders arrive immediately or next day, and whether substitution happens before or alongside A's own demand, both change the Bellman equation. So the reproduction fixes the order first and documents it.

论文没有把这个顺序写全。订货是“立即到货”还是“次日到货”，替代与 A 原始需求是先后还是同时，都会改变 Bellman 方程。所以复现先把顺序固定并写进文档。

Implementation pipeline实现流程

Example: how this differs from the paper's kernel例子：与论文 kernel 的区别

The paper hand-writes a CUDA 8 kernel: one launch per state, with a shared-memory reduction inside each block. The reproduction uses CuPy-generated array kernels that vectorise "gather indices → probability-weighted sum → add reward → take max" over a batch of states. The goal is to reproduce the model and assess current GPU execution, not to copy the kernel line by line.

论文手写 CUDA 8 kernel：一个状态一次 launch，block 内用 shared memory 归约。复现用 CuPy 生成的数组 kernel，把一批状态的“取下标 → 概率加权求和 → 加收益 → 取最大”整体向量化。目标是复现模型并评估当前 GPU 的执行，而不是逐行复刻 kernel。

Remember记住

35–49× is the speedup of this implementation in one Kaggle session, not a cycle-for-cycle reproduction of the original experiment. The paper's baseline is optimised sequential C; the reproduction's is deliberately readable NumPy. What carries over is the trend: the larger the problem, the larger the GPU benefit.

35–49× 是“这个实现在一个 Kaggle session 上”的加速，不是对原实验的逐周期复现。论文基线是优化过的顺序 C，复现基线是刻意保持可读的 NumPy。可比的是趋势：问题越大，GPU 收益越大。

Quiz: Table 3 lists 20,449 states for P2. How should Q be read?小测：Table 3 的 P2 是 20,449 个状态，Q 应该怎么理解？
20,449 = 11² × 13² = (11×13)², i.e. Qₐ=11 and Q_b=13 multiplied directly. If Q were a maximum, it would be (12×14)² = 28,224. So Q in Table 3 is the number of levels.
20,449 = 11² × 13² = (11×13)²，正好是 Qₐ=11、Q_b=13 直接相乘。若 Q 是最大订货量，应为 (12×14)² = 28,224。所以 Table 3 的 Q 是取值个数。
Quiz: why can the paper's P1 profit of 5.509 not be right?小测：为什么论文的 P1 利润 5.509 不可能成立？
Each sale earns at most s − c = 0.5, and long-run total demand is μₐ + μ_b = 10 (substitution moves demand, it does not create it). The ceiling is 5.
每卖一件最多赚 s − c = 0.5，长期平均总需求是 μₐ + μ_b = 10（替代只转移需求，不创造需求），所以利润上限是 5。
Quiz: the reproduction's speedup (49×) is far above the paper's (11.7×). Why doesn't that mean a T4 is 4× faster than a K80?小测：为什么复现的加速比（49×）比论文（11.7×）大得多，却不能说 T4 比 K80 快 4 倍？
The numerators differ: the paper's CPU code is -O3 C, the reproduction's is NumPy, itself roughly 1.2–2× slower. The denominators differ too: kernel design, batching and transfers all changed. The ratio mixes hardware, language and implementation effects.
分子不同：论文 CPU 是 -O3 的 C，复现 CPU 是 NumPy，后者本身就慢约 1.2–2 倍；分母也不同：kernel 设计、批处理和通信方式都变了。加速比混合了硬件、语言和实现三种差异。
5

Conclusions and outlook结论与展望

Conclusion复现结论

The paper's central computational claim holds: value iteration for substitutable perishable products maps effectively to a GPU, and the benefit grows with problem size. The one-product value and policy limit were recovered, the P2–P4 state counts were reconstructed exactly, CPU and GPU values matched to floating-point precision, and P1 waste behaviour closely matched the paper.

论文的核心计算主张成立：可替代易腐商品的价值迭代可以有效映射到 GPU，且收益随问题规模增大。单商品的 π 与策略上限被恢复，P2–P4 状态数精确重建，CPU 与 GPU 数值一致到浮点精度，P1 损耗行为与论文高度吻合。

The reproduction also surfaced several inconsistencies that materially affect interpretation. Recording those assumptions is what makes the results reproducible rather than merely similar.

同时，复现发现若干会实质影响解读的不一致。把这些假设记录下来，结果才是“可复现”，而不只是“看起来相似”。

Limitations局限

The original code is unavailable and the author's response did not resolve the notation and value discrepancies. The P2–P4 counts and P1 waste rates strongly support the adopted interpretation, but cannot prove every low-level transition matches the unpublished implementation. The GPU backend uses generated array kernels rather than Algorithm 5's shared-memory reduction, and the CPU timing is a correctness baseline, not the best achievable CPU performance.

原始源码不可得，作者回复也没有解决记号和数值上的分歧。P2–P4 状态数和 P1 损耗率强力支持当前解释，但无法证明每个底层转移都与未公开实现一致。GPU 后端用的是生成的数组 kernel，而非 Algorithm 5 的 shared-memory 归约；CPU 计时只是正确性基线，不代表最快的 CPU 实现。

What the paper could improve论文可以完善的地方

Add a symbol table separating the maximum quantity Qmax from the number of levels L = Qmax+1, and write N = LaMLbM throughout; state the order of events within a day; run a truncation-sensitivity test with Q̄ = 7, 9, 11, 13; publish parameter files, initial values, the reference state, precision, block size, random seeds and source code; report max CPU/GPU error, action agreement and Bellman residual; and compare against optimised multithreaded C++, reporting kernel, transfer and full-convergence time separately with means and standard deviations over repeated runs.

增加符号表，区分最大数量 Qmax 与等级数 L = Qmax+1，统一写作 N = LaMLbM；写明一天内的事件顺序；用 Q̄ = 7, 9, 11, 13 做截断敏感性分析；公开参数文件、初值、参考状态、精度、block 大小、随机种子和源码；同时报告 CPU/GPU 最大误差、动作一致率和 Bellman residual；用优化的多线程 C++ 作基线，分开报告 kernel、传输和完整收敛时间，并给出重复运行的均值与标准差。

Directions for extension可以拓展的方向

Model模型

More products, different shelf lives, bidirectional or multi-level substitution; non-stationary and correlated demand; random lead times, supply disruptions, fixed ordering costs; markdowns for near-expiry stock as part of the action, giving joint inventory–pricing optimisation.

更多商品、不同保质期、双向或多级替代；非平稳与相关需求；随机交货期、供应中断、固定订货成本；把临期折扣并入动作，做库存—定价联合优化。

GPU methodGPU 方法

Profile, then fuse operations, coalesce memory access and cut branching; partition states across GPUs; compare CuPy, a custom CUDA kernel, JAX, PyTorch and multicore CPU to separate hardware gains from implementation gains.

profile 后融合算子、合并访存、减少分支；按状态划分到多 GPU；对比 CuPy、自定义 CUDA kernel、JAX、PyTorch、多核 CPU，分清收益来自硬件还是实现。

The most promising next step最值得继续做的一件事

Use exact CPU/GPU value iteration as ground truth and ask whether approximate dynamic programming or reinforcement learning can cut computation sharply as the state space grows, while keeping profit and waste close to optimal. Three kinds of experiment: accuracy (profit and policy gaps), scalability (products, shelf life, caps), and business metrics (profit, waste, stock-outs, compute time). This continues the paper's GPU theme and breaks its main limitation to small state spaces.

以精确的 CPU/GPU 价值迭代作为 ground truth，研究状态空间扩大后，近似动态规划或强化学习能否在大幅降低计算成本的同时，保持接近最优的利润与损耗率。实验分三类：精确性（利润与策略差异）、可扩展性（商品数、保质期、上限）、业务指标（利润、损耗、缺货、计算时间）。这既延续论文的 GPU 主题，也突破了它只能处理小状态空间的限制。
